### 需求

#### NEED-001：把抖音直播间接入现有直播插件

- **状态**：confirmed。
- **陈述**：主人可接入抖音直播间，让现有角色根据房间事件在现有本地舞台互动。
- **用户证据**：“然后做完了你再看一看，看能不能也把抖音直播间帮我适配一下 也是可以先找找有没有一些类似的开源项目，再结合你的调研二次验证下做个集成”。
- **目标用户/问题**：当前使用 Harness、GLM 和已有 TTS 的主人；插件仅支持 B 站输入，不能直接用于抖音房间。

#### NEED-002：调研、再验证、再集成

- **状态**：confirmed。
- **陈述**：先比较适用开源方案并二次验证关键能力，再完成有实际使用入口的集成；不能只交调研结论。
- **用户证据**：同 NEED-001 的“先找找……开源项目……二次验证下做个集成”。

### 约束

#### CON-001：保留现有对话、声音与 B 站能力

- **状态**：主方案边界。
- **陈述**：继续使用既有 GLM、声音设置/私有试听和本地舞台。B 站旧设置、隐私选择、数字房间号和已有启动行为在选择 B 站时保持兼容。
- **来源**：主 Agent 给定的当前会话边界，现有 FEAT-001 已发布；不改写 REQ-001/FEAT-001。

#### CON-002：只读房间输入与本地输出

- **状态**：主方案边界。
- **陈述**：本次只读取主人明确选择的抖音房间；角色回复只送现有本地舞台。接入不代表向抖音发弹幕、登录账号或推流。主人的“连接”动作可以开始该房间的只读采集；重启插件不自动采集、不恢复抖音会话、不触发 GLM。
- **来源**：主 Agent 根据用户目标收敛的首期范围与现有外部操作授权边界。

### 决定

#### DEC-001：在既有控制台选择平台、保存房间、连接订阅

- **状态**：主方案选择，原 Spec 已由主 Agent 接受；本轮协议细化见确认日志。
- **采用项**：在现有“直播 → 设置”Drawer 扩展平台选择和抖音房间输入，显示部署配置提供的本地采集地址、采集状态及帮助入口。主人保存后显式连接，看到实际采集状态，再开始本地舞台互动。抖音展示“抖音只读接入 / 本地舞台”，不显示 B 站推流、账号、自己的房间或 B 站黑名单操作。
- **异常行为**：无效房间或保存失败保留输入、解释纠正方式；服务不可达或采集失败显示原因，不伪装已连接。首期只允许主人手动恢复，错误提示“先断开订阅，再显式连接”；不自动重新订阅。舞台运行中、订阅仍存在、B 站操作/清理尚未结束或 OBS/推流仍活动时，平台/目标房间不能切换，须先停止、断开并等待旧操作和清理结束。
- **来源/理由**：主 Agent 已定契约；复用明确的现有 Drawer、控件和 `dl-*` 样式，保持原有操作路径。此为既有明确场景的有限表单扩展，适用包内原型策略的例外，不创建独立原型；没有原型确认或原型验证声明。

#### DEC-002：独立本地采集器由主人管理

- **状态**：主方案选择，原 Spec 已由主 Agent 接受；本轮协议细化见确认日志。
- **采用项**：插件订阅独立本地采集器的指定房间，采集器由主人按操作说明手动运行。插件不接管它的账号、Cookie、浏览器用户资料或进程生命周期。
- **断开语义**：“断开订阅”只停止本插件接收；界面同时说明“采集仍运行，请到采集控制台停止”。停止上游采集由主人在独立采集控制台完成，不由插件停止其他订阅者正在使用的采集。
- **恢复语义**：首次显式连接可能启动采集；传输断开后不自动再连接。上游房间已 closed/error 时，主人先在采集控制台恢复或停止后重开，再在插件断开订阅、显式连接；不能只因再次点击就宣称恢复。
- **来源/理由**：主 Agent 已定契约；二次验证发现订阅可启动上游采集、断开订阅不会停止采集，必须准确展示。具体依赖版本和传输协议在工程上下文定义。

#### DEC-003：事件语义保真与身份隔离

- **状态**：主方案选择，原 Spec 已由主 Agent 接受；本轮协议细化见确认日志。
- **采用项**：支持弹幕、礼物、进场、关注、点赞及房间统计/状态。重复、乱序礼物不能多算；金额未验证时展示数量与礼物名，不称免费或推算人民币，不因未知金额丢失正常热度下的谢礼机会。不把抖音事件伪装成 B 站上舰或醒目留言。
- **身份边界**：本次抖音接入不启用长期观众记忆、B 站账号或 B 站黑名单能力；抖音用户与 B 站相同 ID 字符串不共享记忆、画像、忽略名单或账号动作。断开或允许切换目标时清除旧房间的临时事件、待处理话题、身份/焦点与显示上下文，即使新平台尚未连接也不能把旧人当成新平台用户；保留用户历史、声音和 B 站已保存设置。
- **来源/理由**：主 Agent 已定契约；平台标识、房间、用户和事件 ID 必须保真，防止串房间、串身份和虚构金额。

### 用户场景与测试（必填）

#### 用户故事 1：接入指定房间并在本地互动（优先级：P1）

主人按全局操作入口启动独立采集器，在现有 Drawer 选择抖音、保存房间并连接，然后开始本地舞台互动。独立价值是将已有角色、对话模型和声音用于抖音房间输入。独立测试通过真实控制台、真实插件路由与适配器连接隔离的桥接服务完成；真实房间检查另外标明。

1. **AC-01**：给定舞台未运行且没有活动订阅，当主人输入纯数字房间号或完整 `https://live.douyin.com/<数字>` 并保存、刷新，则平台和房间原样保留；超长整数 ID 不丢精度。短链接、其他主机、额外路径/查询、空值及数值类型输入被拒绝，不访问所输入 URL。
2. **AC-02**：给定本地采集器可用，当显式点击连接，则先显示连接中；只有采集器确认目标房间处于采集中才显示已连接。仅网络连接打开或“订阅接受”不算接通；同一有效状态明确为 live 时，不被同快照遗留的进度错误否定，后来的真实 error/closed 仍生效。采集错误、超时、直播结束、离线、断网均显示错误及“先断开订阅，再显式连接”，不自动重新订阅；上游 closed/error 还须先到采集控制台恢复或停止后重开。
3. **AC-03**：给定已连接目标房间并开始本地舞台互动，当收到有效弹幕/礼物/进场/关注/点赞与统计，则控制台和舞台按既有节奏反映事件，适用话题通过现有对话路径并使用现有声音播放；不向抖音发送文字，不触发 B 站或 OBS。确定性测试观察实际提示词和舞台结果，模型/配音外部消费为零。

#### 用户故事 2：准确理解事件与连接状态（优先级：P1）

主人根据事件与状态决定继续、重试或停止；房间外数据、重复消息和未知金额不能误导互动。独立测试为向真实适配器送受控协议帧并观察插件结果。

1. **AC-04**：给定另一个平台/房间的事件或畸形数据、无效时间戳，当送达当前订阅，则不进入注意力、统计或舞台；事件和用户 ID 保持字符串，相同 ID 的不同平台不串身份。重新订阅后的晚到响应不能改变新状态。
2. **AC-05**：给定同一人同一礼物连击累计数依次为 `1, 3, 3, 2, 3(结束)`，则有界单次订阅窗口内总量为 3、只为正增量更新，重复/乱序/纯结束帧不多算；不同用户/组互不合并。缺少必要连击组标识时丢弃该不可信礼物，不能猜组。金额未知显示未知，正常热度下仍有受节奏约束的谢礼机会；抖音远期上游时间不延迟礼物成熟或过期，调度按本地接收时间；已有 B 站金额、连击和时间语义不变。显式断开重连、窗口外或进程重启不承诺去重连续性。
3. **AC-06**：给定一条点赞聚合携带数量 N，则不伪造 N 条点赞事件；只有有限正安全整数总数可成为已知统计。固定采集器会把缺失点赞/在线/累计观看字段归一为 0，首期无法区分真实零与缺失零，因此这些 0 统一显示未知，不宣称已知零；终态清除旧房间统计，不沿用旧成功数据。

#### 用户故事 3：安全停止、恢复与保留原配置（优先级：P1）

主人可停止本地互动、断开插件订阅，再选择其他房间或 B 站。独立测试覆盖状态切换、重启和既有声音旅程。

1. **AC-07**：给定舞台互动中、存在未断开的订阅、旧 B 站操作/清理尚未结束，或推流准备/人脸等待/推流/停止及所属 OBS 检查仍活动，当修改平台/目标房间，则前后端拒绝并提示先停止、断开、等待完成；生效配置保持原值。即使未开舞台且无订阅，在途账号发布或广播准备也会阻止切换。全部结束后才可保存；断开及切换清除旧临时上下文，新平台尚未连接时，查询主页/私信也不能选中旧平台同 ID 用户。旧异步结果不进入新会话，已接受的一句声音可完成。
2. **AC-08**：给定抖音订阅存在，当点击“断开订阅”，则插件停止接收并清理自身连接、查询和心跳，清除旧房间临时显示，显示“采集仍运行，请到采集控制台停止”；不发送全局停止/删除采集请求，不中断其他消费者。断网后不会自行重新订阅；错误订阅保留锁定直到主人断开。
3. **AC-09**：给定保存了抖音设置和未结束快照，当重启插件，则只保留设置、不自动采集、不恢复舞台互动、不调用模型或 B 站。旧快照未标平台按 B 站解释，但只有当前选 B 站且未开启本地彩排时才允许原有恢复；旧 B 站推流开关不能使抖音启动推流。
4. **AC-10**：给定当前选抖音且本地彩排标志开启，当连接/互动，则页面及给角色的说明明确为“抖音只读接入 / 本地舞台”，已接通时可处理真实房间输入，未接通时不声称已连接；只提供 `show_stats`。模拟观众使用当前平台标记，抖音不提供上舰/醒目留言模拟，空闲提示不建议 B 站视频。B 站账号/社交/私信/游戏/OBS 路径及已加载旧工具执行均受运行时约束，零 B 站 API/Cookie 请求；B 站 ownRooms/记忆/黑名单不影响同名抖音 ID。切回 B 站后的原有行为、声音设置/私有试听和本地费用语义保持。
5. **AC-11（用户确认的本次交付范围）**：给定桌面 1440×900 或窄屏 375×812，当用鼠标完成保存、连接、错误恢复、断开，则控件可操作、没有横向溢出；已覆盖的设置/保存 Enter 与焦点检查保持。地址、状态、连接副作用和停止方式清楚，全局 README 有可用导航到实际操作、参数来源及当前未测范围。完整键盘流程明确列为待验证项，不宣称键盘无障碍完整通过；依用户决定后续处理，不作为本次交付前提。

#### 边界情况

抖音活动订阅包含连接中、已连接及错误后保留的订阅对象，不能仅据“已连接”判断能否切换；B 站原有重连行为保持。保存失败、同时保存与连接、传输失败后断开、B 站在途操作与清理、状态查询晚于推送返回、未来时间、归一化缺失零、重复礼物、未知房间或插件重启均受上述 AC 约束。工程实现的数值上限、超时与缓存容量唯一在工程上下文定义。

#### 关键实体

- **平台与房间目标**：主人选择的输入源；抖音房间号是字符串，区别于 B 站数字房间号。
- **订阅**：插件对本地采集器单个房间的接收连接；它不是采集器本身。
- **房间事件**：带平台、房间、时间和稳定 ID 的输入；礼物组是一次连击的累计数量上下文，金额可未知。
- **本地互动会话**：现有角色、GLM 与声音输出到本地舞台的一场互动；不等于抖音开播或推流。
