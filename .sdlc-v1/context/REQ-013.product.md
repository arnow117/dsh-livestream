# 产品上下文：REQ-013 专用屏幕全屏直播播出与组合验收

## 原始请求与范围来源

- 2026-11-15，用户要求：“这几个需求，我们都推动到验收阶段。完成内部自测后整体联调？画面冻结我们先不做了可以删除掉。其他的都还在。”
- 同轮进一步要求：“就所有需求都推动到仅依赖真实直播间开播状态。”并明确设置持续推进的 Goal，排除等待真实直播的部分。
- 原 [REQ-005](REQ-005.product.md) 已 ready，尚无已登记 Feature。删除其失焦/冻结修复是范围变化，因此本条承接其余播出目标，保留原需求、现场记录、失败和未接受的工程候选，不回写成旧目标已完成。
- 2026-11-15 主 Sol 已接受本规格与 S1–S7 判据；是否 ready、是否已规划/实现/验证，以 `state.json` 为准。来源为已完成的有界 Sol 接续分析，未把分析当实现或运行证据。

## 用户与预期结果

主人在现有 Mac 直播控制台中使用同一直播 Agent、课程和公屏设置，在专用屏幕全屏显示正式舞台。内部实现和必要自测结束后，能够用同一固定候选完成本机组合联调；之后在用户另行安排的直播场次核对独立观众端可见、可听以及获准的公屏发送。

## 范围内

1. 复用已有正式舞台、当前插件与现有播出工具的接线及操作说明，区分有声正式舞台与静音预览。
2. 在前台/专用屏幕全屏运行模式下核对当前回复、字幕、课件画面和音频；保留课程旁白、问答回复与续课的既有规则。
3. 核对输入、回复生成、本机舞台、采集和远端观众各层事实；无法观测的层显示未知，不由推流状态、fps 或本机音频推定远端成功。
4. 保留断线、显式恢复、结束本次 Agent 输出和迟到结果保护：旧事件、已取消回复、待播旧音频不能因恢复补播。结果未知时遵循各原协议，不换请求 ID 重发。
5. 以实际同版插件入口完成课程、公屏与播出组合联调；资料的私有消费只核对隔离边界，不把个人资料带入公共直播 Agent、Stage、TTS 或公屏。
6. 分别交付内部验证结果和真实直播待验清单。已通过的同输入证据可以复用；输入变化或实际缺口需要相应检查，不重复无关完整套件。

## 范围外与运行约束

- 画面冻结、可见失焦、遮挡、Space、最小化等窗口状态的修复与支持扩展已由用户移出当前交付。保留原问题历史，不声明已修复或后台持续播出可用。
- 正式使用约束为专用屏幕全屏显示舞台；锁屏、合盖、休眠和无限时长运行不在承诺内。
- 不新增播出服务、Agent/TTS runtime、另一份舞台或课程管理界面；不采用原未接受的 Electron/OBS 候选，不新增 Douyin 开播/推流 API，不套用 B 站凭据或流程。
- 真实直播场次、真实平台发送/礼物及独立观众观察继续等待用户安排。本轮不自动开播、登录、维护真实发送材料、读取私人 profile 或发送消息。
- 不停止或重启共享 Harness、TTS、DyHub 或其他人的直播；后续本机交付若需要既有服务操作，由主线程按实际已授权目标执行。
- 本条不复制 [REQ-004](REQ-004.product.md) 的私信/登记、[REQ-012](REQ-012.product.md) 的资料写入或 Q 项目的机器人现场业务，不改变其权限和来源合同。

## 成功标准与状态解释

- 内部交付成立：剩余必要实现、内部自测与当前候选的同版组合联调完成，实际命令、版本、配置来源及未测边界可追溯；必要独立验证、Review 和本机交付按生命周期及当前证据执行。
- 全部产品验收成立：在上述内部候选基础上完成获准真实直播及独立观众结果；真实条件未具备时保持该部分未完成，不提前登记整体通过。
- 独立于开播的账号准入、可信资料来源、权限或部署配置缺口不视为直播待验，仍归其原需求推进或具体阻塞，不借本条取消或降级。
