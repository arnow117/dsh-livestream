### 绑定规则

- 内部“全表”描述 owner 的存储/权限视角，不自动授予 Agent 全表检索、枚举、按昵称选人或合并记录的能力。程序只消费本人明确选定的 exact Base/table/record，沿原 SDK admit、组件实例和 grant/revoke 校验。recordId、角色字符串、请求 JSON 或模型输入本身不构成权限。
- 私密原值仅到本人及明确授权的私有组件。Live 与 Robot 各自读取原记录；不让公共模型、turn/tool history、舞台/SSE、TTS/字幕、公屏、普通日志或外部填写者收到原值、记录读链接或附件 token。
- 表单提交、原提交关联、同表回读、两侧消费、资料 readiness、抖音身份及现场识别分别归因。只有原提交与确切记录的可信关系及字段回读成立，才可称该次提交“已核保存”。owner 指定孤立记录只证明 record-only。
- metadata pending/record-only 是合法读取结果；缺版本、用途依据、来源/收集时间不能伪造。照片空不产生识人候选，也不自动成为 ready_no_photo 或识人就绪。已有照片只显示实际状态，本期不下载/核验原附件、不上传或修改。
- 沿父规则保留30天，由用户本人删除；读取不续期，缺实际收集时间不编造起算点；不新增自动删除任务。用途撤销或资料删除后不得复用旧显示或副本。
- 保存仅持久化非秘密引用；显式授权可核本机配置/artifact，但不能登录、探测账号、读业务记录或调用模型。真实资料调用只在显式读取后发生。
