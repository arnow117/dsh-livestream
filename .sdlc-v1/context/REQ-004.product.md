6. **给定**登记期间直播账号/房间断开或切换、旧提交结果迟到，**当**写入/回读结算，**则**有效提交仍按原入口、原 Base/映射版本归因，登记不因设备/直播断连被丢弃；旧结果不关联新直播观众、不触发补发引导。授权撤销或映射不兼容时停止相应新写，保留待核对结果。（CON-001/002）
7. **给定**公开直播画面、声音和其他观众，**当**登记或反馈结果，**则**只给最小非敏感引导/统计，不公开联系方式、照片、登记明细或整表读取入口；外部填写者不能读取/编辑他人记录。Robot 无照片时按其未识别/人工协助规则处理，不要求补照片才算登记。（CON-003、OUT-001）

#### 用户故事 2：公开引导 API 优先，安全使用 UI 备用路径（P1）

**为何此优先级**：让观众找到登记入口，同时避免错房间和重复发布。**独立测试**：在明确运行授权、固定账号/房间及可用发送路径成立后，发送一条不含个人资料的引导；API/UI、平台受理、观众看到及链接/入口可达单独核对。

1. **给定**已绑定授权账号、目标房间和当前有效互动上下文，且有可用 API，**当**执行一项获准公开引导请求，**则**优先从 API 发送到绑定房间；记录该请求和渠道的真实受理结果，另一观众可见须有独立观察，不能以 HTTP 200/工具 accepted/本地回显替代。（NEED-003）
2. **给定**API 经核实不支持或明确不可用，且没有产生待核对的发送副作用，备用 UI 也确认属于同一授权账号/房间、权限及播出状态可用，**当**执行同一引导请求的备用路径，**则**只通过直播伴侣发送一次并标明实际渠道；未确认 UI 目标/状态时保持不可用，不对当前焦点窗口盲输。（NEED-003、CON-002）
3. **给定**API/UI 已派发但超时、断连或首次结果未知，**当**用户重试或考虑切换渠道，**则**保留原请求和绑定目标待核对，禁止切 UI、切 API、换请求标识或重启后重发来掩盖未知；只有核实原结果并确定未发送且仍有当前授权时才可重新执行。平台无幂等支持时不能声称 exactly-once。（分项结果定义）
4. **给定**权限不足、登录过期、用户/房间关系限制、未开播、限流或内容被拒，**当**准备/执行发送，**则**显示有证据的原因和恢复条件，不自动开播、登录、切账号/房间，不用 UI 绕过同一权限/频控；遵守平台重试提示，不能确定是否产生效果时按未知处理。（NEED-003、OPEN-004）
5. **给定**账号、房间、平台或原互动会话已切换，连接断开/撤权，或重复/迟到事件与发送结果到达，**当**处理原请求，**则**旧授权/排队动作失效，不发送到新目标、不自动重放；已派发的原结果只归原请求，不让旧回调覆盖新目标状态。需新的有效绑定才可处理新请求。（CON-002）
6. **给定**公屏可发普通文字但不支持可点击外链，或挂载资格/入口尚不成立，**当**引导登记，**则**如实区分“文字已发”“观众可见”“入口可达”，不声称可点击/已挂载/已登记；仅引用已核实允许的入口，不自行上播飞书外链二维码或将其伪作小程序链接。没有合适入口时显示入口不可用，保留 OPEN-003。（NEED-002/003）
7. **给定**有人要求在引导中附带联系方式、照片、记录详情或把公屏结果称为私信已送达，**当**生成/发送引导，**则**不发送私密资料或虚假结果；对外内容保持为非敏感登记说明。（CON-003、权威规则）

#### 用户故事 3：在现有直播设置面统一配置和理解状态（P1）

**为何此优先级**：用户已明确要求配置并入直播插件。**独立测试**：在现有控制台 Drawer 内用有权限/无权限、未配置、保存失败、能力不可用及结果未知等状态检查配置与恢复反馈；不需要真实发送或上播来证明保存行为。

1. **给定**真实 owner 打开直播控制台设置，**当**管理互动与登记，**则**在同一设置面看清绑定账号/房间、当前发送路径能力、登记入口与 Base/映射引用、共享工具权限状态；复用已有控件和凭据机制，不另开独立后台，不把密钥写进普通设置或回显其值。（DEC-001）
2. **给定**配置尚未读取、为空、未保存、保存中、保存失败、权限不足或某分项不可用，**当**查看/编辑，**则**分别有明确文本状态、可执行恢复动作和必要的禁用原因；保存失败保留草稿与已生效配置的区别。保存成功只表示配置已保存，不自动登录、发送/挂载/开播、探测真实服务或声称表单已提交。（权威规则）
3. **给定**私信不可用而登记资源已准备，或公开引导已受理但可见/入口仍未核实，**当**查看状态，**则**每项独立显示，不用一个“已连接/成功”指示全部就绪，也不因私信红色错误禁掉无依赖登记；已有未知操作保持可见且不能通过重存配置清除。（DEC-003、分项结果定义）
4. **给定**非 owner 或仅 reader 身份，以及窄屏/键盘使用者，**当**操作配置，**则**不能修改受控绑定或提升角色；375px 与 1440px 下关键信息/按钮可达、文字不横向溢出，键盘顺序、可见焦点、标签及状态播报可用，沿现有 Drawer 样式，不新增视觉系统。（DEC-001）

**设计边界**：配置面属于 Operate，核心是分项状态、固定目标和可恢复反馈。复用 `src/console/console.tsx:860` 的设置入口、`:1023` 起的 Drawer 与既有 SecretField；这些源码含 T02 WIP，只读引用，不声称 REQ-004 UI 已存在。本次明确不制作原型，不运行 Impeccable launcher、渲染或 E2E；可访问性条目为未来验收要求。

#### 用户故事 4：保留真实私信收取和正确回复（P1，外部路径受限）

**为何此优先级**：保留原始私信意图，不用独立登记暗中取消。**独立测试**：OPEN-001 具备真实授权路径后，自愿账号发送私聊，核对同一会话的接收、原收件人回复和用户端实际收到；不依赖故事 1/2 通过。

1. **给定**真实获准发送账号、收件人/会话及原消息可信关联，**当**接收并回复私聊，**则**只向该原用户/会话回复；收取、发送受理、实际收到/已读分别归因，登记入口能否到达另核。（NEED-001）
2. **给定**仅有弹幕昵称、DyHub 的待核 ID、模型给定 UID/会话，或账号/关系/权限/频控不满足，**当**请求私信，**则**不猜收件人、不把这些数据当授权、不改用 B 站/公屏/人工代发/模拟抵扣私信；明确未发送、失败或未知。（CON-002）
3. **给定**私信账号/会话断开或切换、重复/迟到事件或发送响应丢失，**当**处理结果/重试，**则**旧动作失效、旧结果留原关联，不重复回复、不盲重发；UID 不经有损 Number 转换，不能每次生成新的 client_message_id 绕开原未知结果。（CON-002、EVD-DM-CANDIDATE）
4. **给定**用户从别的获准入口独立提交且无可信平台关联，**当**同时存在同名私聊，**则**登记保持自报，不自动合并或向该私聊披露记录；入口收到、提交、写表和私信的完成状态独立。（DEC-003）

#### 用户故事 5：Robot 消费同一资料，保护字段所有权（P2）

**为何此优先级**：验证成果可被现场接待直接使用，不重复 Robot 产品。**独立测试**：兼容合同/权限装配后，在不连接 T1 的情况下先验证两侧同表授权查询；现场组合只在另有现场授权时引用 qdroid003 的实际旅程与两仓版本。

1. **给定**故事 1 的真实记录、兼容的共享 Skill/字段配置和已装配 executor，**当**授权 Robot 查询，**则**直接读取同一 Base 中的同一资料记录，保持自报/未关联状态，不从副本或第二 DB 读；源码 interface/Skill 存在不能替代这条真实查询证据。（CON-001/002）
2. **给定**Live 资料更新与 Robot 对原 Visit 的通知/确认/纠错并发，**当**两侧执行，**则**Live 仅 patch 其 Visitors profile 字段，Robot 不整行覆盖 profile，Live 不写 Visits/回退 Robot 状态；身份、权限和映射版本来自受信上下文，不接受模型自报角色。（外部 §7）
3. **给定**重复写/迟到更新、版本冲突、撤权或响应未知，**当**继续处理，**则**保留原提交/记录/版本，不用较旧资料覆盖较新事实；暂停受影响自动写并核对，不凭 read→write→read 宣称 CAS，也不通过整行覆盖“修复”。具体协调方式留 OPEN-002/工程规划。（CON-001/002、外部 §7）
4. **给定**T1 离线、无照片或现场组合未验证，**当**报告结果，**则**不降低已核登记与同表查询的结果，不声称人脸识别/接待已通过；现场识别、到访及一个表情确认仍由 qdroid003 的规则和证据判定。（OUT-001）
